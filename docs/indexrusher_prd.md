## 一、文档概述

### 1.1 产品定位

**IndexRusher** 是一款面向网站所有者、SEO 从业者和内容创作者的 **搜索引擎索引自动化工具**。核心价值是将「手动向 Google、Bing、LLM 搜索引擎提交 URL 请求索引」的重复性工作，转化为全自动化的日常任务，从而缩短新内容从发布到被搜索引擎收录的时间。

### 1.2 产品愿景

> 让每一篇新发布的内容，都能在几小时内被搜索引擎和 AI 发现。

### 1.3 目标

| 目标类型 | 具体目标 |
|---------|---------|
| **业务目标** | 通过 LTD 模式在 12 个月内获取 2000+ 付费用户，ARR 达到 $300K |
| **用户目标** | 将用户网站的平均索引时间从 "数天~数周" 缩短至 "数小时~1天" |
| **产品目标** | 从单一索引提交工具进化为 "索引监控 + 策略优化" 平台 |

### 1.4 成功指标 (North Star Metrics)

| 指标 | 当前基线 (推测) | 6 个月目标 | 12 个月目标 |
|------|--------------|-----------|------------|
| 付费用户数 | ~500 (推测) | 1,200 | 2,500 |
| 用户网站平均索引率 | 未知 | 提升 40% | 提升 60% |
| 每日自动提交 URL 数 | 未知 | 50,000+ | 150,000+ |
| NPS (净推荐值) | 未知 | 40+ | 50+ |
| 月度活跃用户留存率 | 未知 | 60% | 70% |

### 3.2 详细功能需求

| FR-1.2 | 授权访问 Google Search Console 数据 | P0 | 用户需同意访问其 GSC 属性（网站）列表和 URL 状态数据 |
| FR-1.3 | 支持多账号切换 | P2 | 用户可在设置中添加/切换多个 Google 账号 |
| FR-1.4 | 会话管理 | P1 | Token 过期后自动刷新；支持手动登出 |

#### FR-2: 网站管理 (Site Management)

| 需求 ID | 需求描述 | 优先级 | 验收标准 |
|---------|---------|--------|---------|
| FR-2.1 | 自动同步 GSC 属性列表 | P0 | 登录后自动拉取用户 GSC 中所有已验证的网站 |
| FR-2.2 | 手动添加网站 (非 GSC 属性) | P1 | 用户可输入域名和 sitemap URL，系统验证所有权 |
| FR-2.3 | sitemap 自动发现 | P0 | 系统尝试自动发现 `/sitemap.xml` 和 `/sitemap_index.xml` |
| FR-2.4 | sitemap 手动配置 | P1 | 用户可输入自定义 sitemap URL |
| FR-2.5 | sitemap 解析与 URL 提取 | P0 | 解析 XML sitemap，提取所有 `<loc>` 中的 URL |
| FR-2.6 | URL 去重与规范化 | P1 | 自动去除重复 URL，统一处理 trailing slash 和 www/non-www |
| FR-2.7 | 域名配额绑定 | P0 | 每个域名计入用户套餐的 "唯一域名数" 配额 |
| FR-2.8 | 网站删除 | P1 | 用户可删除网站，释放域名配额 |

---

#### FR-3: 索引提交引擎 (Indexing Engine)

| 需求 ID | 需求描述 | 优先级 | 验收标准 |
|---------|---------|--------|---------|
| FR-3.1 | Google Indexing API 提交 | P0 | 每日自动向 Google Indexing API 提交 URL，限额 20 URL/天/网站 |
| FR-3.2 | Bing URL Submission API 提交 | P0 | 每日自动向 Bing 提交 URL，限额 200 URL/天/网站 |
| FR-3.3 | IndexNow 协议提交 | P1 | 支持 IndexNow 协议，向参与该协议的搜索引擎推送 |
| FR-3.4 | LLM 搜索索引提交 | P1 | 通过 Bing 索引间接影响 ChatGPT 等 LLM 的搜索结果 |
| FR-3.5 | 智能 URL 选择策略 | P1 | 优先提交新 URL 和 "crawled but not indexed" 的 URL |
| FR-3.6 | 批量重提交 | P1 | 对长期未索引的页面进行周期性重试提交 |
| FR-3.7 | 去索引请求 | P2 | 支持向搜索引擎提交 URL 移除请求 |
| FR-3.8 | 提交队列管理 | P1 | 可视化提交队列，显示待提交/已提交/失败的 URL |
| FR-3.9 | 提交历史记录 | P1 | 记录每次提交的时间、目标引擎、响应状态 |

**配额策略详细设计：**

```
每日配额分配算法 (Google: 20 URL/day):
├─ 优先级 1: 新增 URL (过去 24h 内出现在 sitemap 中但从未提交过)
├─ 优先级 2: "Discovered - currently not indexed" 状态 URL
├─ 优先级 3: "Crawled - currently not indexed" 状态 URL
├─ 优先级 4: 上次提交超过 7 天的 URL (重试)
└─ 剩余配额: 按 URL 重要性排序 (首页 > 产品页 > 博客页 > 其他)
```

## 八、风险与假设

### 8.1 风险矩阵

| 风险 | 概率 | 影响 | 缓解策略 |
|------|------|------|---------|
| Google Indexing API 政策变化或关闭 | 中 | 🔴 致命 | 多引擎策略；准备 fallback (Search Console UI 自动化) |
| Google API 配额进一步收紧 | 中 | 🟡 高 | 开发智能优先级算法，最大化高价值 URL 的提交 |
| LTD 模式现金流断裂 | 中 | 🟡 高 | 6 个月内推出 PRO 订阅选项；基础 LTD + 高级功能订阅 |
| 用户看不到效果导致 churn | 高 | 🟡 高 | 强化报告的数据洞察；提供 "为什么没索引" 的诊断 |
| 竞品推出免费替代方案 | 高 | 🟡 高 | 快速建立数据壁垒（历史索引数据）；强化生态整合 |
| MarsX 平台限制 | 低 | 🟡 中 | 评估自研后端的技术债务和成本 |

### 8.2 关键假设

1. **假设**：用户愿意为 "自动提交索引" 这个单一功能付费
   - **验证方式**：LTD 早期销售数据；用户访谈

2. **假设**：Google 不会在短期内淘汰 Indexing API 或大幅改善自动索引
   - **验证方式**：持续监控 Google Search Central 博客和 API 变更日志

3. **假设**：LLM 搜索（ChatGPT Search 等）会持续增长，LLM 索引有价值
   - **验证方式**：跟踪 AI 搜索市场份额；用户反馈中 LLM 相关需求的提及率

4. **假设**：LTD 用户会在未来接受订阅制升级
   - **验证方式**：A/B 测试不同的定价页面；早期用户调查

### A. 术语表

| 术语 | 解释 |
|------|------|
| **Indexing** | 搜索引擎将网页添加到其数据库中，使其可以出现在搜索结果中 |
| **Crawling** | 搜索引擎机器人访问网页的过程 |
| **Sitemap** | XML 文件，列出网站的所有重要 URL，帮助搜索引擎发现内容 |
| **GSC** | Google Search Console，Google 提供的网站管理工具 |
| **LTD** | Lifetime Deal，终身授权/一次性付费模式 |
| **IndexNow** | 微软发起的开放协议，允许网站主动通知搜索引擎内容变更 |
| **LLM Indexing** | 让大语言模型（如 ChatGPT）的搜索功能能够索引和引用网页 |
